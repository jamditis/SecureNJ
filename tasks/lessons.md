# Lessons

Rules from corrections and from defects that got through. Read this file at the start of a session.

## 2026-11-18

- **No attribution.** The owner said: "no co-authored commits or copy anywhere". Do not add co-author trailers, session links, or "generated with" text to commits, pull requests, comments, or files.
- **A build that passes is not a working app.** The first release built with no error and produced a blank page, because `index.html` had no entry script. Rule: after a build, open the result in a browser. `npm run e2e` does this.
- **A hard-coded third-party endpoint is a silent failure.** Both signaling servers in the first release were gone, and the UI showed only "Offline". Rule: do not depend on a public service that the group does not control. Show the connection state to the user.
- **Check the shape of library events.** The first release read `webrtcPeers.size` on an array, so the peer count was always empty. Rule: read the type or the source of a library before you use an event payload, and do not type it as `any`.
- **A secure-context API can be missing.** `crypto.subtle` does not exist in a page that is not a secure context. The exported event page failed with no message. The end-to-end test found this, not the unit test. Rule: test an exported file in the same way that a user opens it, and show a message when a browser API is missing.
- **A test must fail without its fix.** Two tests were checked by removal of the fix. Rule 4 in `docs/testing.md`.
- **A library `destroy()` can leave a connection open.** `WebrtcProvider.destroy()` does not close the signaling WebSocket. An independent review found it; my tests did not. Rule: for each "leave", "close", or "delete" action, write a test that observes the outside effect (the socket closes, the database is gone), not only the state of the app.
- **A CRDT database is a log.** Deleted text stayed in the IndexedDB update log. Rule: if the product says "deleted", check the bytes in storage in a test.
- **Do not bind a destructive shared setting to `onChange`.** The retention field deleted posts for the full space while the user typed "72". Rule: a setting that deletes data changes only on an explicit save.
- **One record means one writer.** A post and its claim state were in one record, so an edit and a claim from two devices lost one of them. Rule: before a tool writes a full record, ask who else can write that record at the same time, and split it if the answer is "a different member".
- **Cleanup that lives in a component runs only while the component is on the screen.** Retention ran only in the open tool. Rule: work that must always run belongs in the provider.
- **A test claim must match what the test can observe.** The end-to-end test said "no request to a different host" but could not see WebSockets or STUN. Rule: state the limit of a test in its header, and extend the test or narrow the claim.
- **Get a review from a reader who does not share your assumptions.** Two independent reviews found more than 20 real defects after all my checks were green.
- **Ask the owner only through the question tool.** The owner said: "i only answer via AUQ tool". A question in the text of a message gets no answer. Rule: put each decision that the owner must make in an AskUserQuestion call, with a recommended option first, and make each question complete without the text around it.
- **Read all branches and published builds before you plan.** The live site came from a `gh-pages` build with more tools than `main`, and its source was not in the repository. I found it only when I checked why CI did not start. Rule: at the start of a session, list the remote branches, the open and merged pull requests, and the deploy target, and compare them with the branch you work on.
- **A pull request that conflicts with its base gets no CI run.** CI did not start, with no error, because `main` changed after the branch was made. Rule: when CI does not start, check `mergeable_state` first.
- **A filter on the output hides the exit status.** I ran `node e2e/smoke.mjs | tail -3 && git commit && git push`. The test failed, `tail` returned 0, and the failing commit went to the remote. Rule: never chain a commit or a push after a piped test command. Run the check first with `set -o pipefail` (or with no pipe), read its exit status, and commit in a separate step. `npm run check` has no pipe: use it before each push.
- **Storage belongs to a web origin, not to an app.** My "erase" cleared the storage of the full origin. On GitHub Pages that is every project site of the user. Rule: each key, database, and cache of this app has a name with the app prefix, and code that deletes storage filters on that prefix. A test plants data of a different site and checks that it stays.
- **A CRDT delete can lose against a concurrent write of the full record.** A record that one member deleted came back when a different member edited it at the same time. Rule: a delete of a shared record goes through `deleteRecords`, which leaves a marker.
- **A rule and a generator must be tested against each other.** The passphrase rule refused a word that the passphrase generator can make. Rule: when one function makes values and a second function checks them, a test runs every possible output of the first through the second.
- **A new export path can break a "never on disk" rule.** Backup was added for all tools, and it wrote safety alerts to a file. Rule: when you add a way for data to leave memory (backup, export, cache, log), check it against each "never stored" claim in `docs/security.md` and the limits page.
- **The owner wants no person step.** I made the publish a manual workflow with a confirm word, and I listed "a native speaker reviews the Spanish text" as a task. The owner said: "i dont want a person to start it lol. i just want it to happen automatically. auto translation and auto deploy please". Rule: the default design is the automatic one. Put a manual gate in a design only when the owner asks for it, and do not recommend it as the first option. Do not make open tasks that a person must do when a machine can do them. (My reading: this is about work steps. It does not change the rule that the owner decides through the question tool.)
- **A workflow that cannot run before merge needs its logic in a script with tests.** The publish workflow is tested for the first time on `main`. Rule: keep the logic of a workflow in a script that a test can run with stand-ins, and make the last step check the real result (the live site), not only the exit status of a push.
- **Subagents use Opus 5.5 at medium effort.** I started five translation agents on the model of the session. The owner said: "you should be using opus 5.5 medium effort subagents not fable btw". Rule: each Agent call sets `model: opus` and `effort: medium`, unless the owner names a different model for a task.
- **Do not add a machine where an agent already does the work.** I planned a translation engine in CI (LibreTranslate), installed it, and wrote a client for it. The owner said: "we could just translate it ourselves" and "the content isnt gonna be changing too much and we can just make sure to have agents translate any new content". Rule: before you add a service, a container, or a workflow step, ask if the agent that makes the change can do the same work in the pull request. Then make a test that fails when the work was not done (here: a stale translation fails the lint).
- **Do not run `git checkout HEAD -- <path>` to tidy up.** I restored a folder that I had removed on purpose. Rule: look at `git status` first, and name the exact file.
- **The tool that opens a pull request adds an attribution line.** The body of pull request 7 got a "Generated by" footer that I did not write. Rule: after each create of a pull request, read its body back and remove the footer with an update. The same holds for comments.
- **A check must pass its own source.** A new rule for addresses refused the correct translations of one message, because the English text itself did not pass the rule (a file name that starts with a dot). Rule: when a rule compares a text with its source, a test runs the source through the rule as its own translation.
- **A stamp must record what the worker read, not what is current when the stamp is written.** A command that stamped all translations "as current" could mark a translation of old English text as current. A review found it, with a test of mine that treated the hole as correct. Rule: evidence of freshness is written by the same step that does the work, from the input that the work used.
- **State the part of the work that you did not read.** Agents ported seven tools. I did not read each line, and I said so in the pull request, then had two independent reviews read the full change.
